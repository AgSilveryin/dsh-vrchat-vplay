| 截图被遮挡窗口的问题 | ✅ 已修复 `player/tools/capture_frame.ps1`（AttachThreadInput + HWND_TOPMOST 临时置顶，截完还原） | 修复前后对比见 `diag-*`、`aim-servo-*` 截图 |
| **Phase 4：连续 5 次选中同一菜单项** | ✅ **5/5 通过**（每次都是"导航首页→设置页"，5 次 after 图像相互差异 0.61–1.16%，证明同一项） | `node tools/aim-click-accept.mjs`；证据 `shots/live/aim-accept-2026-11-05T04-18-37-*`（20 张截图 + json） |

**Phase 4 是怎么解决的**：把左手（菜单）挪到右手射线的正前方——左手 `target=(-0.05,1.35,0.45)`/`rot(yaw 10,pitch -20)`、右手 `(0.28,1.42,0.34)`/`rot(0,0)`，此时 2D 激光端点必然落在面板表面，扳机点击命中"设置"页签；关/开菜单（B、B）回到首页，可重复。判定：菜单区域变化 >10%（实测 24.6–25.4%），且 5 次 after 相互差异 <8%（实测 0.61–1.16%）。完整循环平均 **23.7 s**（含开关菜单与 5 张截图；点击指令本身即时）。

**仍属"几何法"，不是任意目标 3D 反解**：这次靠"把目标移进射线路径"实现命中；要做到"镜头里任意菜单项都能点"，还需用 `lib/aim3d.mjs` 标定菜单平面做射线求交（工具已备好，26 项单测）。另外绝对标定（手部原点/激光偏移/FOV 是否严格 90°）仍未做；目标像素仍靠人工给（未做 UI 元素自动识别）。

**历史排查记录**（第二轮 2026-11-04，见 `docs/C-瞄准方案.md` §11.4）：曾测到"2D 激光端点对准 ≠ 3D 射线打中 UI 面板"——菜单区域点击前后 0 像素变化；VRChat 绑定里 interact 确实绑模拟扳机（0.7/0.55）。这两个事实是找到"把菜单挪进射线"方案的关键。

## D. 自家 avatar 头部遮挡视野（当前配置未复现）

- 截了一张当前第一人称画面：`shots/live/D-firstview-check.png`。
- 结果：**视野中心是镜子/世界画面，没有自家 avatar 头部遮挡**；画面左下角能看到自家模型身体/手臂、右下角是手柄模型。
- 诚实结论：HANDOFF §8-D 描述的"Robot avatar 头部挡在画面中间"在**当前 avatar（浣熊模型）下未复现**——很可能是用户已换 avatar 或该模型自带正确第一人称相机。
- 通用解决办法（未实施，需要用户资产配合）：换带正确第一人称相机/隐藏头部的 avatar；或给插件加"HMD 位置前移"配置（治标，约 0.5 天）；或在 avatar 上加相机偏移（用户资产）。

## H. soak + 崩溃恢复

### H-1 第一轮（22:53–23:00，约 8 分钟 + 2 次崩溃演练，未满 1h）

**做了（真实数据，2026-11-04 22:53–23:00）**

- 启动方式：`vrchat_player({action:"start", live:true, perception:"vision", nav:"on", seconds:1800})`。
- 启动基线（22:53:20）：player RAM 70.7 MB、CPU 2.1 s；`/health` fps≈61；录像目录 20 文件 78 MB（上限 30 文件 / 256 MB）。
- 连续运行段（22:53–22:58:40，约 5.7 分钟）：**fps 稳定 60–61、仿真时间与真实时间 1:1（10.15 s / 10 s 实测）、RAM 稳定在 ~126–140 MB（无泄漏性增长）、录像持续写入、`recording.error=null`、`pruned=0`**。
- **崩溃演练 1（kill VRChat，22:56:50）**：
  - 插件不崩：`vrchat_status` 仍 `listening:true`、`connected:false`、事件缓冲到上限 600；`vrchat_doctor` 降级为「体检通过一半」并给出下一步「启动 VRChat」；
  - 玩家进程继续跑：15 s 后 60fps、35 s 后 60fps（视觉得不到 VRChat 画面时按剧本兜底，不崩溃）；
  - VRChat 重启后（22:57:51）knuckles binding 重新加载，玩家进程继续。
- **崩溃演练 2（kill 玩家进程，22:58:40）**：看门狗 **2 秒后**拉起新 node 进程（pid 5348 → 27036），监视器 `/health` 从 0 重新计数、fps 61，`pruned=0`；之后录像继续写（21 文件 134 MB）。
- 结论：**插件降级/看门狗/录像上限三条行为符合 HANDOFF §6，未发现泄漏性增长**。
