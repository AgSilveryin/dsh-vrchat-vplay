# VRChat 联调清单

> 用途：VRChat 打开后，按顺序确认「插件 ↔ VRChat」这条线是否通。每步都对应一个 agent 工具。

## 0. 前置（人来做）

1. 正常方式启动 Steam（**不要从 DSH 沙盒里启动**）→ 启动 VRChat → 登录 → 进入任意世界（home 世界也行）。
2. 确认 OSC 开启：**Action Menu → Options → OSC → Enabled**（VRChat 一般默认开启）。
3. 如果机器上还有别的 OSC 工具（面捕、OSCLeash、心跳/震动类），先关掉或确认它们不占 9001。

## 1. 链路检查

| 检查 | 工具 | 期望 |
| --- | --- | --- |
| 插件在听 VRChat | `vrchat_status` | `listening: true` |
| VRChat 在发参数 | `vrchat_status` | `connected: true`（最近 10 秒收到过 UDP 包） |
| 当前 avatar | `vrchat_status` | `avatarId` 是 `avtr_...` |
| 参数列表 | `vrchat_list_params` | 至少能看到 `GestureLeft/Right`、`Grounded`、`Voice` 一类 |

`connected` 一直是 false 时：
- 还没进世界 / 还在加载 → 进世界后再看；
- OSC 被关了 → 打开 Action Menu 里的 OSC；
- 端口被改过 → 看 `%USERPROFILE%\AppData\LocalLow\VRChat\VRChat\osc.json` 里的 `in`/`out`，和插件 `cordis.patch.yml` 的 `sendPort`/`listenPort` 对齐（VRChat 默认 out=9001，插件默认 listenPort=9001）。

## 2. 说话检查

```
vrchat_say({text: "你好，我是接到 VRChat 里的 AI，测试 chatbox。"})
```

游戏里角色头顶应该出现气泡。注意：

- 同世界玩家都看得到，别发隐私；
- VRChat chatbox 有冷却，经验值是 **1.5 秒/条**（社区工具 VRC-OSC 的说明也这么写），插件默认按 1500ms 排队；
- 单条有行数/字符上限，插件会自动切分成长度合规的多条；
- 如果气泡不出现，先确认 chatbox 没被世界/设置屏蔽，再试 `vrchat_osc_send({address:"/chatbox/input", args:["test", true, false]})` 直接发原始包。

## 3. 感知检查（玩家 → AI）

玩家做动作时，agent 侧应该能收到参数变化：

```
vrchat_wait({param: "GestureLeft", timeoutMs: 20000})   // 挥左手
vrchat_wait({param: "Grounded", timeoutMs: 20000})      // 跳跃（false）/落地（true）
vrchat_events({since: 0, includeNoisy: true})           // 看全部流水（含 Voice/Velocity）
```

默认会过滤 `Voice`、`Viseme`、`VelocityX/Y/Z` 这类高频参数（避免刷屏），需要时用 `includeNoisy: true` 或 `vrchat_list_params` 直接看快照。

## 4. 控制检查（AI → 玩家角色）

```
vrchat_input({action: "Jump", holdMs: 120})
vrchat_input({action: "MoveForward", holdMs: 800})   // 按住前进 0.8 秒
```

- 桌面模式：效果应该和按键盘一样；
- VR 模式：移动/视角通常仍由手柄摇杆控制，`/input` 可能只对跳跃/交互类动作有效，需要实测确认。

## 5. 陪玩玩法示例（用默认 avatar 就能玩）

- **是/否 问答**：约定「挥左手=是，挥右手=否，跳一下=不确定」，agent 用 `vrchat_wait` 等手势。
- **你画我猜**：玩家用 `GestureLeft/Right` 组合表示数字，agent 猜。
- **跟随模式**：agent 读 `VelocityZ`（`includeNoisy:true`）+ `vrchat_input(MoveForward)` 跟着走。
- **表情回应**：`vrchat_set_param({name:"VRCEmote", value: 1..})` 触发表情动作（取决于 avatar 支持）。
- **节奏游戏**：agent 每隔几秒 `vrchat_say` 一个动作指令，玩家照做，agent 用 `vrchat_events` 计分。

## 6. 头部 / 位姿 / 转头检查（需要 A 线 HMD 驱动或自编译 VMT 驱动 + VR 模式）

> 完整协议、坐标系换算、参数与真机验收步骤见 [`vmt-pose.md`](./vmt-pose.md) §2–§3（头部）与 §5–§6（手部/转头）。
> 这里只放联调时的快速检查项。

前置：SteamVR 已起、VRChat 已由 A 线驱动进 VR（`dsh_hmd.DSH_HMD`，log 有 `StartVRSDK: OpenVRLoader`）；
手部要验的话 VMT 驱动也已加载（`vrserver.txt` 当前会话有 `Loaded server driver vmt`）。

### 6.1 头部（A 线驱动，39572）

| 检查 | 操作 | 期望 |
| --- | --- | --- |
| 驱动探活 | 先 `vrchat_head` 一次，再 `vrchat_status` | `head.driver.driverAlive: true`、`reason:"port-in-use"`、`port:39572` |
| 真转头 | `vrchat_head({rotation:{yaw:90}, durationMs:1000, hold:false})` | 画面**平滑**右转 90°；返回 `openvr.to.rotation≈(0,-0.707,0,0.707)` |
| 抬头/低头 | `vrchat_head({rotation:{pitch:30}, durationMs:800})` / `pitch:-30` | **抬头看天** / 低头看地（方向反了就是换算问题，记录 `openvr` 值） |
| 位置 | `vrchat_head({target:{z:0.5}, durationMs:600})` | 头部前移 0.5m（Unity +Z → OpenVR -Z） |
| 抢占 | `yaw:90, durationMs:2000, wait:false` 后立刻 `yaw:-90, durationMs:300` | 第一次返回 `interrupted:true`，头部平滑转向新目标、无瞬移 |
| hold 呼吸 | `hold:true` 等 10 秒 | 头部保持，极轻微漂移（≤4mm/0.3°）；`status.head.holdActive:true` |
| 没装驱动 | 停掉 A 线驱动后调 `vrchat_head` | **不报错**；`driver.alive:false` + `warning`；`vrchat_say` 等仍正常 |

### 6.2 手部（VMT，39570）

| 检查 | 操作 | 期望 |
| --- | --- | --- |
| 驱动探活 | 先 `vrchat_pose` 一次，再 `vrchat_status` | `pose.driver.driverAlive: true`；`pose.driver.lastUnavailable: 0` 表示 RoomMatrix OK |
| 位姿平滑 | `vrchat_pose({hand:"right", target:{x:0.4,y:1.3,z:0.35}, durationMs:800, hold:false})` | 游戏里右手**平滑**到点（不是瞬移），返回 `frames≈48`（60Hz×0.8s） |
| hold 微动作 | 同一次调用改 `hold:true`，等 5–10 秒 | 手保持位置，只有极轻微漂移（≤ ±1.2cm）；`status.pose.holdActive: true` |
| 抢占 | `vrchat_pose({..., wait:false})` 后立刻再调一次 | 第一次返回 `interrupted:true`，手从当前位置继续、无跳变 |
| 交还双手 | `vrchat_pose({cancel:true, disable:true})` | 动作停止；真实手柄重新接管 |
| 没装驱动 | 停掉 VMT 后调 `vrchat_pose` | **不报错**；`driver.alive:false` + `warning`；其他工具正常 |

### 6.3 转头（`vrchat_look` 分流）

| 检查 | 操作 | 期望 |
| --- | --- | --- |
| auto 用真转头 | A 线在线时 `vrchat_look({angleDeg:90})` | 返回 `mode:"head"`；视线平滑转 90°；**没有** `/input/LookHorizontal` 包 |
| 转头+抬头 | `vrchat_look({angleDeg:90, pitchDeg:20})` | 右转 90° 并抬头 20° |
| 面向点 | `vrchat_look({target:{x:1,y:1.6,z:0}})` | 面向 +X（yaw 90°） |
| 强制 snap | `vrchat_look({mode:"snap", angleDeg:90})` | 返回 `mode:"snap"`；VR + Comfort Turning 下 2 次 45° |
| 驱动消失回退 | 停掉 A 线后 `vrchat_look({angleDeg:90})`（auto） | 返回 `mode:"snap", headAvailable:false` |
| 强制 head 但不可用 | `vrchat_look({mode:"head", angleDeg:90})` | 降级 snap，`fallback:true` + `warning` |
| 桌面模式 snap | 桌面模式 `vrchat_look({mode:"snap", angleDeg:90})` | 平滑小转（不等于 45°，属预期；snap 语义只在 VR 成立） |

### 6.4 崩溃看门狗与端口

| 检查 | 操作 | 期望 |
| --- | --- | --- |
| 崩溃看门狗 | 发位姿期间盯 `vrserver.exe` + `<Steam 安装目录>\dumps` | 无新 `crash_vrserver.exe_*`；有 dump 立即 `vrchat_head({cancel:true})` / `vrchat_pose({cancel:true,disable:true})` 并记录参数/时间点 |

## 7. UI 操作真机验证清单（0.6.0 新增）

> 前置：驱动已用 `vrchat_drivers({action:"install"})`（或 `drivers\install-drivers.ps1`）装好并**重启过 SteamVR**；VRChat 在 VR 模式；面板 `http://127.0.0.1:8790/` 可开（可选）。
> 顺序：先离线、再真机；先看、再点。**失败项如实标记**，不要跳步。

### 7.1 驱动与 binding（先确认底座）

| 检查 | 操作 | 期望 |
|---|---|---|
| 驱动注册 | `vrchat_drivers({action:"status"})` | `ready=true`、两个驱动 `present && registered`、`external_drivers` 有 `drivers\dsh_hmd` 与 `drivers\vmt` |
| VMT 加载 | 看 `vrserver.txt` | `Loaded server driver vmt`、`Driver 'vmt' finished adding tracked device` |
| knuckles binding | 看 `vrserver.txt` | `[Workshop] Successfully loaded binding file ...bindings_knuckles.json... for app 'steam.app.438100'`，且**没有** `has no configured binding` |
| 虚拟手柄渲染 | 进 VR 看双手 | 显示 knuckles 模型 + 激光 |

### 7.2 UI 操作（每步先截图、再操作、再截图）

| 检查 | 操作 | 期望 / 注意 |
|---|---|---|
| 眼睛 | `vrchat_screenshot` | 返回 headset 画面；桌面模式下回退 VRChat 窗口（前提 VRChat.exe 在跑） |
| 打开 Quick Menu | `vrchat_ui({action:"openQuickMenu"})`（左手 B） | 菜单出现；前后 `vrchat_screenshot` 对比可见差异 |
| 激光指向 | `vrchat_pose({hand:"right", target:{...}})` 把右手移到菜单项前 | 激光指向目标；位姿平滑不瞬移 |
| 扳机点击 | `vrchat_ui({action:"select"})`（右扳机） | UI 状态变化（进入子菜单/选中高亮），再用 screenshot 确认 |
| 抓取 | `vrchat_ui({action:"grab"})`（右 grip）、再 `release` | 在有 Pickup 的世界能抓/放；Home 里没有可抓物时"没反应"属正常 |
| 摇杆 | `vrchat_ui({action:"stick", x:0, y:1, durationMs:300})` | 菜单里上下移动选择 |
| 松开全部 | `vrchat_ui({action:"release"})` | 所有键/扳机归零，不会"卡键" |
| Action Menu | `vrchat_ui({action:"openActionMenu"})` | 现为**长按 B（600ms）**（推断值：VRChat knuckles 绑定里 B→`/actions/global/in/menu`，长按分流在游戏内）；如实记录阈值是否合适 |
| dashboard 隐藏 | `vrchat_ui({action:"hideDashboard"})` 或面板按钮 | **0.6.0 已可用**：走 `vrcmd.exe --hidedashboard`（实测输出 `HideDashboard`）；更彻底用 `steamvr.vrsettings` 关掉自动弹出 |
| 完整闭环 | 打开菜单 → 指向 → 扳机点击 | 0.6.0 实测已打通到"摇杆移动角色 / B 开菜单 / 扳机点击被 SteamVR 接收"；"激光指向具体菜单项再点击"仍需按本节逐项过（依赖手部姿态朝向） |

### 7.3 看门狗（异常退出自动重启，由插件 `vrchat_player` 管理）

| 检查 | 操作 | 期望 |
|---|---|---|
| 正常结束不重启 | `vrchat_player({action:"start", seconds:5})` 等它跑完 | 不触发重启；`status.watchdog.reason="completed"` |
| 异常退出会重启 | 启动后从外部杀掉子进程（`taskkill /PID <pid> /F`） | 约 `backoffMs=2000` 后自动重启；`watchdog.restarts` +1、`lastRestartAt` 有值 |
| 预算用尽 | 连续杀掉 4 次 | 默认 `maxRestarts=3`（10 分钟滚动窗口）→ `watchdog.exhausted=true`、`reason="exhausted"`，不再重启 |
| 主动停止不重启 | `vrchat_player({action:"stop"})` / 面板点"停止" | 不再重启；`reason="stopped"` |
| 状态字段 | `vrchat_player({action:"status"})` | `watchdog:{enabled,restarts,maxRestarts,lastRestartAt,exhausted,reason}` |

### 7.4 录像上限（monitor）

| 检查 | 操作 | 期望 |
|---|---|---|
| 默认上限 | 连续跑几段 demo、看 `<recordDir>` | 最多保留 `30` 个文件 / `256 MB`（默认 `recordMaxFiles` / `recordMaxBytes`）；开新录像前按 mtime 从旧到新 prune |

## 8. 常见故障

| 现象 | 原因 / 处理 |
| --- | --- |
| `listening: false` + `listenError` | 9001 被其他 OSC 程序占用：关掉它，或改 `listenPort` 并同步改 VRChat `osc.json` |
| `connected: false` 但 VRChat 在跑 | OSC 未开 / 玩家不在世界 / 端口不一致 |
| chatbox 没气泡 | 世界或设置禁用 chatbox / 发送太快被限流 / 文本为空 |
| 中文乱码 | VRChat 支持 UTF-8；若显示异常，先确认不是字体/世界 UI 问题（编码层已有往返测试） |
| 参数收不到但 chatbox 能发 | 说明 VRChat→本机方向不通：检查 `osc.json` 的 out 端口、防火墙、其他 OSC 工具劫持 |
| `pose.driver.driverAlive: false` | VMT 驱动没装 / SteamVR 没起 / 进 standby / 被 safe mode 拉黑；工具只降级不报错，见 `vmt-pose.md` §5.4 |
| `head.driver.driverAlive: false` | A 线 HMD 驱动没装/没起 / 39572 没有进程在听；工具只降级不报错，见 `vmt-pose.md` §3.4 |
| `head.driver.driverAlive: null` | 端口探测失败（权限/驱动绑的地址不是 127.0.0.1）；确定驱动在时可设 `headDriverAssumed: true` |
| 头部调用后画面不动 | 驱动没收到 / VRChat 不在 VR / `dsh_hmd` 驱动未加载；先看 `status.head.driver` 与 VRChat log |
| 转头方向/俯仰相反 | OpenVR 右手系换算问题；记录 `vrchat_head` 返回的 `openvr` 值与截图，对照 `vmt-pose.md` §2.1 |
| 手在位姿工具调用后不动 | RoomMatrix 未设置 / VRChat 不是 VR 模式 / enable 模式不匹配（试 `vmtEnableMode:"controller"`） |
| 插件的 `pose.driver.listenError` 提示端口占用 | 39571 被别的工具占用（如同时跑 `motion.mjs`）：改用其他端口或等插件空闲释放 |
