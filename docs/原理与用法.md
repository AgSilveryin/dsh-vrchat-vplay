# 原理：把 agent 接进 VRChat 的那条线

> 本文写清楚「为什么能接」「怎么接」「接进去之后能干什么、不能干什么」。协议细节以 VRChat 官方 OSC 文档为准；本文的实现细节对应本仓库 `lib/osc.js`、`lib/bridge.js`、`index.js`。

> **两条位姿通道 + 一条兜底，全部"没驱动就自动降级"**：
> - **头部**：A 线自研 HMD 驱动 `dsh_hmd`（`/dsh/head/pose` → UDP 39572，OpenVR 右手系）——真转头/抬头；
> - **手部**：自编译 VMT 驱动（`/VMT/Room/Unity` → UDP 39570，Unity 左手系）——左手/右手位姿；
> - **转头兜底**：VRChat `/input/*` 的 snap turn（不需要驱动）。
>
> 驱动没装/没起时工具**不报错**，只返回 `driver.alive=false|unknown` + `warning`，OSC-only 能力完全不受影响。
> 旧的 `TrackingOverrides → /user/head` 会让 vrserver 崩，已废弃。协议、坐标系换算、失败模式与真机验证步骤见
> [`vmt-pose.md`](./vmt-pose.md)。

## 1. VRChat 的 OSC 到底是什么

VRChat 客户端内置了一个 **OSC over UDP** 服务（Open Sound Control，一种给多媒体/游戏传参数的轻量协议）：

- VRChat **监听** 一个 UDP 端口，接收外部发来的 OSC 消息（默认 `127.0.0.1:9000`）。
- VRChat **发送** avatar 参数等状态到一个 UDP 端口（默认 `127.0.0.1:9001`）。
- 两个端口都可以通过 `%USERPROFILE%\AppData\LocalLow\VRChat\VRChat\osc.json` 重映射，本插件对应 `sendPort` / `listenPort` 配置。
- 它**只在本机回环地址**上工作，不经过 VRChat 服务器；也就是说这条链路是「本机程序 ↔ 本机 VRChat」。

OSC 消息本身很简单：

```
/avatar/parameters/GestureLeft   ,i   0x00000002
└────── address ──────┘          │    └─ 参数（int32 / float32 / bool / string）
                                └─ 类型标签串，逗号开头
```

字符串是 UTF-8、NUL 结尾、按 4 字节对齐；数字是大端。VRChat 的 chatbox 能收中文（UTF-8）。这些编解码在本仓库 `lib/osc.js` 里手写实现（无第三方依赖），`tools/osc-selftest.mjs` 有往返测试。

## 2. 插件结构

```
┌────────────────────────── DSH Host 进程 ──────────────────────────┐
│  index.js（插件入口，注册 19 个工具）                              │
│    ├─ 对话/感知：vrchat_status / say / list_params / events / wait │
│    ├─ 操作：set_param / input / move / osc_send                    │
│    ├─ 位姿：pose（VMT）/ head（dsh_hmd）/ look（auto）             │
│    ├─ 编排：player / player_preflight / mode（一键挡位）           │
│    ├─ 体检：doctor（lib/doctor.mjs，只读探测本机栈）               │
│    ├─ lib/bridge.js ── UDP ──┬─→ 127.0.0.1:9000 ─→ VRChat          │
│    │                         └←─ 127.0.0.1:9001 ←─ VRChat          │
│    ├─ lib/vmt.js（手部）── UDP ─→ 127.0.0.1:39570 ─→ VMT 驱动      │
│    │                          └←─ 127.0.0.1:39571 （Alive 探活）  │
│    ├─ lib/head.js（头部）── UDP ─→ 127.0.0.1:39572 ─→ A 线 HMD 驱动│
│    │                          （无回包；用端口占用探活）            │
│    ├─ lib/look.js ── snap turn 走 bridge 的 9000；auto 时委托 head  │
│    ├─ lib/player-process.mjs ── spawn ─→ player/demo.mjs           │
│    │     （playerDir 自动探测：包内 player/ → 兄弟工程 → 旧路径）   │
│    └─ lib/launch.mjs ── 按 Steam → SteamVR → VRChat 顺序启动缺的     │
└───────────────────────────────────────────────────────────────────┘
```

`lib/bridge.js` 做三件事：

1. **发**：把工具调用编码成 OSC，发给 VRChat（chatbox / avatar 参数 / input）。
2. **收**：监听 9001，解析 VRChat 发来的 `/avatar/parameters/*`、`/avatar/change` 等，维护「参数最新值表」和「事件环形缓冲」。
3. **等**：给 agent 提供长轮询 —— `vrchat_wait` 会阻塞到某个匹配事件到达或超时，返回事件 + 参数快照。

对话循环就靠这三件事拼起来：

```
agent 说一句话          → vrchat_say → chatbox 气泡
agent 等玩家反应        → vrchat_wait(GestureLeft) → 玩家挥手
agent 对挥手做出回应    → vrchat_say / vrchat_input(Jump) ...
```

`vrchat_wait` 是「听」的关键：它让一次模型回合内可以持续在游戏里陪玩，而不需要玩家回 DSH 界面打字。

## 3. 各个方向能做到什么

### 3.1 说 —— `/chatbox/input`

```js
bridge.say('你好')  →  /chatbox/input ["你好", true, false]
                        └ 文本   └ 立即发送 └ 提示音
```

- 文本显示在角色头顶的 chatbox 气泡里，同世界玩家可见。
- VRChat 对 chatbox 有**长度限制（按行 144 字符、最多 9 行）**和**发送冷却**；超长会被截断，发太快会被丢弃。插件在 `lib/bridge.js#splitChatboxText` 里按行切分，并用队列保证两条消息间隔 `chatboxMinIntervalMs`（默认 1500ms）。这些数值都可在 `cordis.patch.yml` 的 `config` 里改。
- 发消息前会先发 `/chatbox/typing true`，队列清空后发 `false`（可关）。

### 3.2 看 —— `/avatar/parameters/*`

VRChat 会把当前 avatar 的 animator 参数持续通过 OSC 发出来。默认 avatar 就自带这些「传感器」：

| 参数 | 含义 | 用途 |
| --- | --- | --- |
| `GestureLeft` / `GestureRight` | 左手/右手手势编号（0–7） | 玩家挥手、指人、握拳 → AI 可当作按钮 |
| `Grounded` | 是否站在地面 | 跳跃检测（true→false→true） |
| `VelocityX/Y/Z` | 移动速度 | 跟着玩家走、判断方向（高频，默认被过滤） |
| `Voice` | 说话音量 0–1 | 知道玩家在说话（高频，默认被过滤） |
| `Viseme` | 口型 | 同上 |
| `Upright` | 站立/倒地 | 状态判断 |
| `VRCEmote` | 表情动作编号 | 双方表情互动 |

自定义 avatar 还能暴露任意参数：模型作者在 Expression Menu / Animator 里加一个参数，OSC 就能读到 → 玩家可以用菜单按钮给 AI 发「是/否/选项 1/选项 2」这类信号。插件把全部参数都存下来，`vrchat_list_params` 可查当前快照，`vrchat_events` 可看变化流水。

**注意：VRChat 不会通过 OSC 把「玩家打的字」或「玩家说的话」发出来。** 语音也只有一个音量值 `Voice`。所以玩家 → AI 的信息通道只有 avatar 参数，这一点无法绕过（除非额外做语音转写，那是另一条独立管线）。

### 3.3 动 —— `/input/*`

`vrchat_input(action, holdMs)` 模拟本机输入，例如：

`Jump`、`Voice`、`MoveForward`、`MoveBackward`、`MoveLeft`、`MoveRight`、`LookLeft`、`LookRight`、`LookUp`、`LookDown`、`Grab`、`Drop`、`Use` ……

- 发送的是「按下」布尔值；`holdMs > 0` 时插件会在指定毫秒后补发松开，实现「按住走一段」。
- 和玩家自己按键是同一个输入通道，所以菜单打开等情况下可能被 VRChat 忽略；VR 模式下移动仍由手柄摇杆主导，`/input` 的效果要在实际客户端里验证。

### 3.4 摆手 —— `vrchat_pose`（VMT 驱动，降级可用）

`/input/*` 只能按键，给不了"手停在哪"。手部位姿走 SteamVR 侧的虚拟设备：本插件把目标位姿按 30–90Hz
平滑发给本机 **VMT 驱动**（UDP 39570），驱动变成 SteamVR 里的虚拟手柄，VRChat 再从 SteamVR 取姿态。

```js
// 右手 0.8 秒抬到胸前，然后保持（默认 hold:true）
vrchat_pose({ hand: "right", target: { x: 0.3, y: 1.4, z: 0.25 }, durationMs: 800, easing: "easeOut" })

// 双手同时（不同目标），结束后交还真实手柄
vrchat_pose({ hand: "both",
              left:  { target: { x: -0.35, y: 1.35 } },
              right: { target: { x:  0.35, y: 1.35 } },
              durationMs: 500, hold: false })

// 后台播放 + 抢占 / 停止
vrchat_pose({ hand: "left", target: { y: 1.5 }, durationMs: 2000, wait: false })
vrchat_pose({ hand: "left", target: { y: 1.2 }, durationMs: 300 })   // 打断上一段
vrchat_pose({ cancel: true, disable: true })                          // 停 + 交还双手
```

- 坐标：米，Unity 左手系（X 右 / Y 上 / Z 前），相对房间原点；`y≈1.6` 大约眼高。
- **不会瞬移**：内部定时器循环插值；`wait:false` 时立即返回、后台继续；新调用会抢占旧调用（旧调用返回 `interrupted:true`）。
- `hold:true`（默认）到达后继续喂位姿，并叠加拟人层 idle 微动作（≤ ±1.2cm / ±0.4°）；`hold:false` 结束时发 `enable=0` 把双手还给真实手柄。
- **没装 VMT 驱动时不报错**：仍返回成功，但 `driver.alive=false` + `warning`，包发出去没人收。
- **只做手**：头部由 A 线 HMD 驱动 + `vrchat_head` 负责（见 §3.5）。
- 完整参数、返回结构、失败模式、真机验证步骤：[`vmt-pose.md`](./vmt-pose.md) §5。

### 3.5 转头/抬头 —— `vrchat_head`（A 线自研 HMD 驱动）

A 线驱动（随包 `drivers/dsh_hmd/bin/win64/driver_dsh_hmd.dll`）直接提供 HMD 位姿：插件把目标头部位姿
按 **90Hz** 平滑发给 `127.0.0.1:39572` 的 `/dsh/head/pose`（7 个 float，**OpenVR 右手系**）。
这是**真转头**，不再是 snap turn 近似；而且能抬头/低头。

```js
// 向右转 90°，1 秒完成，然后保持（默认 hold:true，带呼吸微动）
vrchat_head({ rotation: { yaw: 90 }, durationMs: 1000 })

// 抬头 30°、头部前移 0.5m（位置与 vrchat_pose 一样用 Unity 左手系，内部转 OpenVR）
vrchat_head({ rotation: { pitch: 30, yaw: 0 }, target: { z: 0.5 }, durationMs: 800 })

// 后台播放 + 抢占 / 停止
vrchat_head({ rotation: { yaw: 45 }, durationMs: 1500, wait: false })
vrchat_head({ rotation: { yaw: 0 }, durationMs: 400 })   // 打断上一段
vrchat_head({ cancel: true })                             // 停流（驱动保持最后一帧）
```

- 位置/四元数入参与 `vrchat_pose` 同一套 **Unity 左手系**；内部换算成驱动要的 **OpenVR 右手系**
  （位置 `z` 取反、四元数 `qz/qw` 取反、w 归正）。**不要直接把 OpenVR 值喂给 `vrchat_pose`，反之亦然。**
- 欧拉角语义：`yaw + = 右转`、`pitch + = 抬头`、`roll + = 右歪`（比 Unity 原生直觉）。
- 新调用抢占旧调用；`hold:false` 到达后停流；`cancel:true` 立即停。
- **A 驱动没有回包**：可用性靠"39572 端口是否被占用"探测（`driver.alive=true/false/null`），
  确定环境可用配置 `headDriverAssumed` 强制。没驱动时照发包、只警告。
- 细节（坐标系换算表、失败模式、返回结构、真机验证）：[`vmt-pose.md`](./vmt-pose.md) §2–§3。

### 3.6 转头 —— `vrchat_look`（auto：优先真转头，兜底 snap turn）

`vrchat_look` 是高层"看"接口，默认 `mode:"auto"`：**A 线头部可用就调 `vrchat_head` 真转头（精确角度 + pitch），
否则退回 VRChat snap turn**。

```js
vrchat_look({ angleDeg: 90 })                        // auto：有 A 线 = 平滑右转 90°；无 = 2 格 snap
vrchat_look({ target: { x: 1.0, y: 1.6, z: 0 } })    // 面向世界点（head 模式会同时算 pitch）
vrchat_look({ angleDeg: 45, pitchDeg: 20 })          // 转头 + 抬头（仅 head 模式）
vrchat_look({ mode: "snap", angleDeg: 90 })          // 强制 snap turn
vrchat_look({ angleDeg: 180, planOnly: true })       // 只算计划，不发包
```

| `mode` | 行为 |
| --- | --- |
| `auto`（默认） | 头部可用（39572 被占用）→ `vrchat_head`；否则 snap |
| `head` | 强制真转头；驱动不可用时**降级 snap**，结果里 `fallback:true` + warning |
| `snap` | 强制 snap turn；`snapMode:"axis"`（默认）或 `"comfort"` |
| `axis` / `comfort` | 旧值，等价 `mode:"snap"` + 对应子模式 |

- 真转头模式：`angleDeg` 相对 yaw；`target` 同时算 yaw 与 pitch；`pitchDeg` 追加俯仰；`durationMs` 不给就按角度估算。
- snap turn 模式：把角度换算成 N 次 `stepDeg`（默认 45°），每次 `1 → 0`，中间夹 180–320ms 人类式随机间隔；
  朝向只能累计估计（`currentYawDeg` 可校准）——这是兜底方案的硬限制。
- 中断（`exec.signal`）时 snap 会补发 0，不会让视角一直转；真转头会停在当前朝向上。
- 细节：[`vmt-pose.md`](./vmt-pose.md) §6。

### 3.7 挡位与体检 —— `vrchat_doctor` / `vrchat_mode`（0.5.0 新增）

这两个工具是给"不想记参数"的人用的，语义是**挡位**而不是接口：

| 挡位 | 做什么 | 需要 |
|---|---|---|
| `chat` | 只走 OSC：chatbox / 参数 / `/input/*`；不发位姿、不启玩家 | VRChat 在跑即可 |
| `demo` | 演练：`player/demo.mjs --live` **不带**，只把三维骨架喂给监视器 `http://127.0.0.1:8765/` | 无（不碰 VR） |
| `player` | 真机：`--live`，感知默认 `vision`（纯视觉）、导航默认 `on` | Steam + SteamVR + VRChat + 驱动 |
| `stop` | 停玩家进程，把位姿交还真实设备 | 无 |

- `vrchat_mode({ preset:"player" })` 在启动前会先跑一次体检；没过就直接返回"下一步该开什么"，**不会**盲启动一个发不出包的进程。
- 加 `launch: true` 时按 **Steam → SteamVR → VRChat** 顺序启动缺的部分（Steam 没起的顺序会害 VRChat 弹"Steam 无法启动"模态，这是实测坑）。
- 正在跑时改 `perception` / `nav` 会**自动按新挡位重启**，不需要先 stop。
- 感知四挡：`off`（零 IO）/ `vision`（只截图、绝不读日志，实机默认）/ `log`（只读日志、绝不截图）/ `hybrid`（日志轮询 + 事件触发截图）。截图目标是 SteamVR 的「Headset Window」，解码与名字牌检测全部在包内 `player/src/perception/`，纯 Node、零依赖。
- `vrchat_doctor` 的 11 项检查覆盖：Node 版本、玩家文件（含 `playerDir` 解析来源）、VRChat / Steam / SteamVR 进程、`dsh_hmd` 与 VMT 驱动证据（优先读 `vrserver.txt`，其次端口探测，并标注 `SO_REUSEADDR` 可能误判）、OSC 端口占用、Headset 窗口、VRChat 日志目录、监视器端口。返回 `verdict` + 至多 3 条中文 `nextSteps`。

### 3.8 虚拟手柄 / 截图 / 驱动 / 本地面板（0.6.0 新增）

0.6.0 把"能动手"补齐成一条完整的手眼链：**先看（截图）→ 摆手（位姿）→ 用手指点（虚拟手柄）→ 再看（确认）**。

#### 3.8.1 `vrchat_ui` —— 像人一样按虚拟手柄（VMT `/VMT/Input/*`）

- 驱动：随包 `drivers/vmt`（安装见下）；VMT 现报 **knuckles** 类型，所以 VRChat 自带的 `bindings_knuckles.json` 生效（实测 vrserver `[Workshop] Successfully loaded binding file ...bindings_knuckles.json... for app 'steam.app.438100'`，不再报 `has no configured binding`）。
- 协议（VMT 源码 Index 兼容分支；`idx` 1=左手、2=右手，`timeoffset` 恒 0）：
  - `/VMT/Input/Button`（system=0 / a=1 / b=3）、`/VMT/Input/Button/Touch`
  - `/VMT/Input/Trigger`（trigger=0 / grip=1，float 0..1）、`/VMT/Input/Trigger/Touch|Click`
  - `/VMT/Input/Joystick`（trackpad=0 / thumbstick=1，x/y）、`/VMT/Input/Joystick/Touch|Click`
- `vrchat_ui` 的 `action`：
  | action | 含义 |
  |---|---|
  | `press` | 按键一次：`button` = `system`/`a`/`b`/`grip`/`trigger`/`thumbstick`/`trackpad`；`side` 左/右；`durationMs` 默认 `uiPressMs=140`；`value` 可给 trigger/grip 0..1 模拟量 |
  | `stick` | 推摇杆：`x`/`y` = -1..1（`side` 选左右手） |
  | `release` | `releaseAll()`：松掉所有按住的键/扳机/摇杆 |
  | `openQuickMenu` | 快捷菜单 = 左手 **B** |
  | `openActionMenu` | Action Menu = 左手 **A**（当前实现；与"长按 B"的游戏内分流不同，**待真机确认**） |
  | `select` / `use` | 右扳机 |
  | `grab` | 右 grip |
  | `hideDashboard` / `showDashboard` / `dashboardStatus` | 走 SteamVR 自带 `vrcmd.exe --hidedashboard/--showdashboard`（实测输出 `HideDashboard` / `ShowDashboard(  )`）；找不到 vrcmd 时退回向 `dsh_hmd` 发 `/dsh/dashboard/hide|show`（可选能力） |
- 所有按键/轴都是"**脉冲**"：发出后 `durationMs` 自动归零，归零包一定发（不节流），不会把键卡在按下状态；插件卸载时 `uiReleaseAllOnUnload` 默认再兜底全松一次。
- 模拟量：`value < 1` 时 trigger/grip 走 `/VMT/Input/Trigger` 的 float 数值；否则按一次完整按键。

#### 3.8.2 `vrchat_screenshot` —— agent 的"眼睛"

- 截 **SteamVR「Headset Window」** 返回图片给模型（经宿主 attachments 落盘为 image content）。
- **回退规则**：找不到 Headset Window 时回退到标题含 `VRChat` 的窗口，但**只有 `VRChat.exe` 在跑时**才允许回退（否则浏览器标题里带 VRChat 会把整个浏览器截进来，这是踩过的坑）。回退进程名可用 `screenshotFallbackProcess` 改。
- **只读**：不发任何输入；超时 `screenshotTimeoutMs=4000`（可配）。失败返回 `ok:false + attempts`，不抛异常。

#### 3.8.3 `vrchat_drivers` —— 随包驱动的装/卸/查

- `drivers/` 内自带 `dsh_hmd`（虚拟 HMD，`/dsh/head/pose`→39572）与 `vmt`（虚拟手柄/追踪器，`/VMT/Room/Unity`→39570、`/VMT/Input/*`）以及 `install-drivers.ps1` / `uninstall-drivers.ps1`。
- `action="status"`：**只读**，返回 `driversRoot`、每个驱动的 `{name, dir, present, registered, dll}`、`external_drivers` 列表，以及汇总 `ready / filesPresent / registered`。
- `action="install"` / `"uninstall"`：调用 `drivers/install-drivers.ps1`（或卸载脚本）；脚本用 `vrpathreg` 写 `openvrpaths.vrpath`，**幂等**、自动找 SteamPath、`-Force` 处理旧路径、`-WhatIf` 干跑；**装完必须重启 SteamVR**。
- 安装超时 `driversInstallTimeoutMs=120000`；驱动目录可用 `driversDir` 改（空 = `<插件根>/drivers`）。

#### 3.8.4 本地面板（`http://127.0.0.1:8790/`）

- `panelEnabled` 默认 true；只绑回环（`panelHost` 非回环会被强制回退到 127.0.0.1），端口 `panelPort=8790`。
- 页面按钮：体检 / 演练 / 真机 / 停止 / 关掉·显示 SteamVR 面板 / 松开所有键 / 开监视器 / 左·右 / A·B·Trigger·Grip / 摇杆四向；SSE 实时显示操作日志；`POST /api/action` 有**动作白名单**，越权动作拒绝；面板不读文件、不执行 shell。
- 白名单还包含 `status` / `screenshot` / `driversStatus` / `installDrivers`（供页面/脚本调用）；**当前页面模板未放"截图/装驱动"按钮**——需要时直接用 `vrchat_screenshot` / `vrchat_drivers` 工具（或后续补按钮）。
- 面板调用的就是同一套工具（doctor/mode/ui/player/screenshot/drivers），因此调试面板与 agent 行为一致。

## 4. 拟人层（`lib/humanize.js`）
"像人"不靠堆指标，靠**可调、可复现的随机性**。本插件的拟人层是纯函数（无 socket/定时器），
所有随机都能用 `seed` 复现，便于回归测试：

| 能力 | 实现 | 用在哪 |
| --- | --- | --- |
| 反应延迟 | 对数正态（默认中位 400ms、σ=0.35，夹 120–1600ms） | `vrchat_pose({reaction:true})` 开始动作前 |
| 动作时长抖动 | `base × (1 ± 8%)` | `vrchat_head` / `vrchat_pose` 的 `durationMs` |
| 间隔不重复 | 区间随机 + 相邻值去重 | `vrchat_look` 的 snap 间隔 / 按压时长 |
| idle 微动作 | 由 `(seed, t)` 决定的双正弦叠加，平滑且有界 | 手部 hold（≤±1.2cm/±0.4°）、头部 hold 呼吸（≤±4mm/±0.3°） |
| 缓动 | `linear` / `easeOut` / `easeInOut` | 头部/手部位姿插值曲线 |

设计原则：**决策层只下"意图"（目标点/角度/时长），拟人化是原语层的属性**，可以单独调参、单独单测。
函数清单与测试见 [`vmt-pose.md`](./vmt-pose.md) §7–§8。

## 5. 安全与边界

- 链路只走本机 UDP 回环，不经过网络；但**任何本机程序**都能往 9000 发 OSC（VRChat 不验证来源），所以别把它当成权限边界。
- chatbox 是公开可见的：发出去的文字同世界玩家都能看到，别让 agent 把隐私内容念出来。
- 插件不持久化任何聊天内容；参数表只在内存里滚动缓存。

## 6. 怎么启用 / 排错

**第一步永远是 `vrchat_doctor`**：它只读、约 2 秒，会直接告诉你缺什么、下一步做什么（不用猜）。

1. 启动 VRChat（Steam → VRChat），登录，进入任意世界。
2. 打开 **Action Menu → Options → OSC**，确认 **Enabled**（VRChat 一般默认开启；改过 `osc.json` 的话确认端口一致）。
3. 在 DSH 里调 `vrchat_status`：`listening=true` 表示插件在 9001 上等 VRChat；`connected=true`（最近 10 秒收到过包）表示 VRChat 正在发参数。
4. 调 `vrchat_say({text:"测试"})`，看游戏里头顶气泡是否出现。
5. 若 `listenError` 提示端口占用：多半是别的 OSC 工具（OSCLeash、面捕软件等）也占着 9001，改 `listenPort` 并同步改 VRChat 的 `osc.json`，或关掉那个工具。
6. **头部（可选）**：确认 SteamVR/VRChat 已由 A 线驱动接管（`dsh_hmd.DSH_HMD`）、UDP 39572 在听；
   调一次 `vrchat_head` 后看 `vrchat_status.head.driver.driverAlive`（`true` = 端口被占用，驱动在）。
   没装驱动时该值为 `false` 且工具返回 `warning`，是**预期降级**。真机验证清单见
   [`vmt-pose.md`](./vmt-pose.md) §9。
7. **手部（可选）**：确认 VMT 驱动加载（`vrserver.txt` 有 `Loaded server driver vmt`）；调一次 `vrchat_pose`
   后看 `vrchat_status.pose.driver.driverAlive`。没装时同样只降级。
8. `node tools/test_head.mjs` / `test_pose.mjs` / `test_look.mjs` / `test_humanize.mjs` 不需要 SteamVR，可先离线验证软件侧。
9. **SteamVR dashboard/Desktop 视图盖住 VRChat 怎么办（0.6.0 已解决）**：dashboard 在 `startDashboardFromAppLaunch=true` 时会随游戏启动自动打开盖住画面，合成的 system 键又会被 SteamVR 过滤（按了不关）。两种解法：① **推荐**：在 `%SteamRoot%\config\steamvr.vrsettings` 里把 `steamvr.startDashboardFromAppLaunch` 与 `dashboard.enableDashboard` 设为 `false`（先备份，重启 SteamVR 生效；本机实测有效）；② 运行时：`vrchat_ui({action:"hideDashboard"})` / 面板"关掉 SteamVR 面板"按钮，走 `vrcmd.exe --hidedashboard`（实测可用）。`vrchat_mode({preset:"player"})` 启动时会自动 hide 一次。日志侧证据：vrserver 里 VMT 的 knuckles binding 已加载（`Successfully loaded binding file ...bindings_knuckles.json`）。
